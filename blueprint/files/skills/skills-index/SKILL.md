# Skills index

The entry point for "which skill should handle this?". It describes how the
catalogue is organised, how to read the live list, how to route a request, and
which skills chain together. It deliberately does not carry a fixed skill count:
the catalogue grows, and the generated index is the authority.

## Read the generated index first

The live catalogue is `blueprint/files/skills/_meta/SKILLS-INDEX.md`, regenerated by
the installer after every install run. On this machine:

`C:\Users\Riley\Desktop\DeerFlow Forge\blueprint\files\skills\_meta\SKILLS-INDEX.md`

It lists every skill directory with its trigger summary, line count, version and
per-runtime status (`current`, `missing`, `differs`), plus any skill failing
validation. Read it at use time. Never quote a count from memory, from a prompt, or
from this file.

```powershell
$SKILLS = "C:\Users\Riley\Desktop\DeerFlow Forge\blueprint\files\skills"
Get-Content "$SKILLS\_meta\SKILLS-INDEX.md"
```

If the index is missing or older than the last source change, regenerate it with the
installer before routing:

```powershell
python "$SKILLS\_meta\install_skills.py" --targets both
```

## What is in the catalogue

Skills are grouped by the job they finish, not by tool. The stable families are:

| Family | Job | Core skills |
|---|---|---|
| Vector and raster craft | Clean a raster, trace it to editable SVG | `artcraft-image-cleanup`, `artcraft-vector-trace` |
| Print production | Provider-ready masters, inserts, tags, embroidery art | `apparel-print-master`, `shipping-card-tag`, `embroidery-art` |
| Brand system | Logo variants, palette, type, print rules, templates | `brand-system` |
| Marketing art | Paid social stills, website banners | `ad-creative`, `web-banner` |
| Meta tooling | Install, validate and route skills | `skill-installer`, `skills-index` |
| Command knowledge | Map any job/menu to exact ids, full indexes, tips, recipes | `artcraft-command-atlas`, `artcraft-command-catalog` |
| Vector editing | Geometry, type, layers/artboards/symbols, colour/styles, export, SVG | `artcraft-path-geometry`, `artcraft-typography-outlines`, `artcraft-layers-artboards-symbols`, `artcraft-color-swatches-styles`, `artcraft-document-export-formats`, `artcraft-svg-production` |
| PhotoCraft production | Layers/smart objects, selections/masks, adjustments/filters, batch automation | `artcraft-photocraft-layers`, `artcraft-selections-masks`, `artcraft-photocraft-adjustments-filters`, `artcraft-batch-automation` |

New skills appear in the generated index as they are added; treat the table above as
orientation, not as the roster. Runtime roots may also contain skills that are not
managed by this repo; the generated index covers repo-managed skills only.

## How to discover

1. Read `_meta/SKILLS-INDEX.md` and match the request against the trigger summaries.
2. For a machine route, run `python "$SKILLS\_meta\install_skills.py" --check --json`
   and inspect each skill's `valid`, `description_chars`, and target `status`.
3. List the directories that actually contain a `SKILL.md`:

   ```powershell
   Get-ChildItem $SKILLS -Directory | Where-Object { Test-Path (Join-Path $_.FullName "SKILL.md") } | Select-Object -ExpandProperty Name
   ```

4. Confirm the chosen skill is `current` in both runtimes before relying on it. A
   `missing` or `differs` status means install it first, not that the instructions
   are unavailable.
5. Open the full `SKILL.md`; read the workflow, gates and refusal conditions before
   executing anything.

## How to trigger a skill

- Match the user's **intent and phrasing** to the skill's description, not just to
  its name. Descriptions carry the phrases a user actually says.
- Prefer the narrowest skill that finishes the job. Use a chain only when one skill's
  output is another skill's input.
- Load the whole `SKILL.md`; the index summary is a pointer, never the instructions.
- State which skill you are using and why, then follow its workflow exactly.
- If two skills overlap, choose the one whose output matches the requested
  deliverable, or chain them explicitly.
- If nothing matches, say so and describe the closest capability. Never improvise a
  skill, and never claim one exists without reading the index.

## Chains

| Chain | Order | Boundary |
|---|---|---|
| Brand to downstream | `brand-system` → `ad-creative` / `web-banner` / `shipping-card-tag` / garment lockups | Downstream skills consume the kit; they do not re-derive colours or type |
| Clean to trace | `artcraft-image-cleanup` → `artcraft-vector-trace` | Cleanup fixes the source; trace consumes the cleaned raster |
| Trace to print | `artcraft-vector-trace` → `apparel-print-master` → publish | Publish changes the live store and needs explicit owner approval |
| Embroidery is terminal | `embroidery-art` → art plus constraints | Never present the output as a stitch file; a digitizer produces that |

Meta chain: `skill-installer` changes what exists, then `skills-index` routes to it.
Regenerate the index after every install; never hand-edit the generated file.

## Routing examples

| Request | Route |
|---|---|
| "Turn this logo into an SVG" | `artcraft-vector-trace` |
| "Clean up this scan, then vectorise it" | `artcraft-image-cleanup` → `artcraft-vector-trace` |
| "Put this design on a shirt" | `apparel-print-master` (after brand system if no kit exists) |
| "Build the brand kit first" | `brand-system` |
| "Make a thank-you card" | `shipping-card-tag` |
| "Make an Instagram ad" | `ad-creative` (with `brand-system` output) |
| "Website hero banner" | `web-banner` |
| "Cap embroidery design" | `embroidery-art` |
| "Is this skill valid and installed?" | `skill-installer` |

## Maintenance

- Add or edit a skill in the repo, validate it, then run the installer; the index and
  manifest regenerate in the same run.
- Do not write skill counts or a frozen roster into this file, a prompt, or another
  skill. Read the generated index instead.
- When a runtime copy drifts, the index shows `differs`; replace it deliberately with
  `--force` after inspecting both hashes.

## Failure modes

| Symptom | Cause | Action |
|---|---|---|
| Index lists a skill that is gone | Index not regenerated after a removal | Rerun the installer |
| A skill exists but is not in the index | No `SKILL.md`, or validation failed | Run `validate_skills.py` and read the failure |
| Route feels ambiguous | Two skills overlap | Choose by requested deliverable, or chain them |
| Runtime status `missing` | Skill not installed in that root | Install with `--targets both` |
| Runtime status `differs` | Source changed after install, or local edit | Inspect hashes; reinstall with `--force` when intended |
| User names a skill not in the index | Wrong name or not in this repo | Say so, list the closest matches from the index |

## Verification checklist

1. Index read directly from `_meta/SKILLS-INDEX.md` in this session.
2. Chosen skill's row is `current` for both DSH and Hermes.
3. Full `SKILL.md` opened, not only the index summary.
4. Chain order stated when more than one skill is involved.
5. Output handed off only at the boundary the receiving skill documents.

## Non-negotiables

- The generated index is the roster; this file is the map.
- Never state a skill count without reading the index.
- Never execute a skill from its summary alone.
- Never route to a skill that is missing or stale in the target runtime.
