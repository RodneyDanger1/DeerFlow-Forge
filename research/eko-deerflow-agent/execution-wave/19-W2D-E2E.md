# W2-D — service↔repository seam, worker and reaper end-to-end

**Date:** 2026-11-05 · **Scope:** local + throwaway PostgreSQL 16. **No production DB, service or deploy.**
Gate: `docs/W2D-GATE1.md`.

## Change

- `make_server(..., repo_factory=...)` creates the repository **on the service's own event loop**, fixing
  the caller-loop/pool mismatch.
- HTTP responses serialize asyncpg `UUID`/`datetime` values (`default=str`); repository rows decode
  JSONB `payload/result/budget/params` back into Python objects.
- Duplicate episode idempotency key returns **409 `E_EPISODE_EXISTS`**, not a 500.
- Read/create failures return **503 `E_SERVICE_UNAVAILABLE`** and are logged; no silent exception.
- `LeaseReaper` runs bounded, cancellable iterations of `reap_expired_jobs`, logs a failed iteration and
  continues.

The 9 skips are explicit: 4 pre-existing DB-dependent tests, 3 repository tests and 2 end-to-end
tests when `FORGE_TEST_DSN` is unset.

## Seam defects found and fixed

1. `json.dumps` now handles `UUID`/`datetime` at the HTTP boundary; response previously crashed and
   closed the connection.
2. `claim_job` returned `payload` as raw JSON text; worker received a string and `dict()` failed.
   `ForgeRepo._row` decodes JSONB fields.
3. Service pool was bound to the caller's loop; `repo_factory` creates it on the service loop.
4. Duplicate episode creation was an unhandled unique violation; now a named 409.
